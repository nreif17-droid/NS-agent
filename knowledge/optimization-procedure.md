# Optimization Procedure: Baseline → High Performance

**Labeling note (same as `regularization-procedure.md`):** this is original synthesis sequencing cited components, not itself a validated bundled protocol. It only applies once `regularization-procedure.md` Stage 4 (baseline) is actually met — advanced-tier tools are hormetic stressors (see `protocols-advanced.md` framing note) and are the wrong tool for someone still dysregulated.

## Prerequisite gate

Do not enter this procedure if:
- The person's log shows recent (same week) use of the regularization procedure for an unresolved cause (Stage 3 causal layer still open).
- Any advanced-tier contraindication applies (cardiovascular conditions, disordered-eating history, panic disorder relevant to breath-hold work) — re-check per protocol, not assumed clear from a past check.

This gate exists because advanced-tier tools (cold exposure, breath-hold, fasting) are all **sympathetic activators or metabolic stressors** — appropriate hormesis for a regulated system, counterproductive or risky for a dysregulated one. This is the single most important design rule carried over from `protocols-advanced.md`.

## Default sequence

### Stage 1 — Establish personal baseline data
Before optimizing anything, the log needs enough entries to know what "normal" looks like for this specific person (see `regularization-procedure.md` Stage 4 — no population-norm baseline exists in this knowledge base for HRV or similar markers). Practically: this stage may just be "keep logging" for a new user, not an active protocol.

### Stage 2 — Pick one lever, not all of them
Evidence quality varies a lot across advanced-tier tools (`protocols-advanced.md` quick-reference table). Recommended default order by evidence strength + risk profile:
1. **HRV resonance-frequency breathing** — strongest evidence (meta-analytic support), lowest risk. Good default starting lever.
2. **Sauna/heat exposure** — strong cohort evidence, low risk (screen cardiovascular status first).
3. **Cold exposure** — plausible mechanism, weaker downstream-benefit evidence, low-to-moderate risk (screen cardiovascular status first).
4. **Fasted-state training** — mixed/duration-dependent evidence, moderate risk (eating-disorder screen mandatory).
5. **Breath-hold/cyclic hyperventilation work** — real safety risk category; only after the above are established, and only with the water/isolation safety rules from `protocols-advanced.md` §3 stated every time, unconditionally.

This ordering is this agent's own risk-weighted prioritization, not a literature-derived sequence — flagged as such.

### Stage 3 — Single-variable testing via the log
Change one lever at a time and log outcomes (see `/logs/` design in the CLI proposal) before stacking multiple advanced protocols — otherwise the personal case log can't actually attribute what's working, which defeats the brief's stated purpose for keeping the log at all.

### Stage 4 — "Leveling up" definition
Operationally: sustained baseline improvement (per Stage 1's personal-baseline data) *while* the Stage 2 lever's dose is held constant or reduced — i.e., the person needs less input to maintain the same state. This is a reasonable definition of adaptation/resilience consistent with the hormesis framing in `protocols-advanced.md`, but — like the rest of this file — it's this agent's design choice, not a cited standard.

## Why this differs from regularization

Regularization is about matching urgency (fast tools for acute states, causal tools for recurring problems). Optimization is about **controlled, attributable stress** — the entire point is applying a known stressor and measuring adaptation, which only works with a stable baseline and single-variable changes. Rushing straight to advanced-tier stacking (cold + fasting + breath-hold all at once) would make it impossible to know what's producing any observed change, independent of the elevated risk profile.
